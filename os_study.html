Unit 1 - Introduction to Operating System

1.1 Operating System Kya Hai?

OS ek special software hai jo hardware aur user ke beech bridge ka kaam karta hai.

Simple words: OS ek translator hai jo user ki language samajhta hai aur hardware ko samjhata hai.

OS ke Functions:

  • Process Management: CPU allocate karna, scheduling karna
  • Memory Management: RAM allocate/free karna
  • File System: Files organize karna, CRUD operations
  • I/O Device Management: Devices handle karna
  • Security: Unauthorized access se bachana
  • User Interface: CLI ya GUI dena

1.2 Classification of Operating Systems

1. Batch OS

User interact nahi karta. Jobs cards/tapes pe load hote hain, OS execute karta hai.

  • Example: Payroll, Bank statements
  • Fayda: Same type jobs efficiently
  • Nuksan: Zero interaction, debugging mushkil

2. Time Sharing OS

Har user ko time slice milta hai. Example: UNIX, Linux, Windows. Direct interaction, kam response time.

3. Real-Time System (RTS)

Time ka strict hona zaroori hai. Hard RTS: Deadline miss=failure (Airplane, Pacemaker). Soft RTS: Quality down (Video streaming). Example: Traffic control, Medical monitoring.

4. Multi-Programming System

Multiple programs memory me hain, CPU ek time pe ek execute karta hai. I/O wait pe switch hota hai.

Multiprogramming vs Multitasking:
FeatureMultiprogrammingMultitasking
CPUEk time pe ek activeMultiple active lagte hain
Time SharingI/O tak ek pe rehtaHar ko time slice milta hai
ExampleEarly batch systemsWindows, Linux, Android
InteractionKam ya zeroDirect interaction
Context SwitchKamZyada

5. Multiprocessor Systems

2+ CPUs ek saath kaam. Throughput, economy, reliability badhti hai.

6. Multiuser Systems

Ek system pe multiple users (UNIX/Linux terminal).

7. Multithreaded Systems

Process ke andar multiple threads parallel execute. Code/data share, apna stack.

1.3 OS Structure

  1. Process Manager: Creation, deletion, suspension
  2. Memory Manager: Allocation, paging, segmentation
  3. File Manager: File operations, directory
  4. I/O Manager: Device allocation, buffering
  5. Storage Manager: Disk management
  6. Network Manager: Protocols, communication
  7. User Interface: CLI/GUI

1.4 OS Services

  • Program Execution: Load karna aur run karna
  • I/O Operations: Files/devices se I/O
  • File Manipulation: CRUD operations
  • Communication: Inter-process communication
  • Error Detection: Errors handle karna
  • Resource Allocation: CPU, memory, I/O allocate
  • Protection: Unauthorized access se bachana
  • Accounting: Resource usage track karna

1.5 Kernels

Kernel OS ka core hai jo hardware se directly baat karta hai. System calls ke through communicate karte hain.

1.6 System Calls

System Calls = interface jisse user programs OS services use karte hain.

  1. fork(): Naya process create karta hai parent ki copy
  2. exec(): Naya program load karta hai, purana replace hota hai
  3. wait(): Parent child ka wait karta hai

2.3 Process Synchronization

Multiple processes ek shared resource access karein to race condition ho sakti hai.

PROCESS:
  +------------------------+
  | Entry Section          |
  | CRITICAL SECTION       |
  | Exit Section           |
  | Remainder Section      |
  +------------------------+
  • Mutual Exclusion: Ek time pe sirf ek CS me
  • Progress: Koi free ho to koi bhi ja sakta hai
  • Bounded Waiting: Zyada der wait nahi

2.4 Semaphores

Semaphore = integer variable. Operations: wait() aur signal().

semaphore s = 1; // Binary semaphore wait(s) { s = s - 1; if (s < 0) { block process; add to waiting queue; } } signal(s) { s = s + 1; if (s <= 0) { remove P from waiting queue; wakeup(P); } }

Binary: 0/1 (mutex). Counting: positive integer (resource count).

2.5 Synchronization Problems

1. Producer-Consumer (Bounded Buffer)

semaphore mutex = 1; semaphore empty = n; // buffer size semaphore full = 0; producer() { while(true) { item = produce(); wait(empty); // buffer full to wait wait(mutex); // CS me jao add item; signal(mutex); // CS chhodo signal(full); // consumer ko notify } } consumer() { while(true) { wait(full); // buffer empty to wait wait(mutex); item = remove(); signal(mutex); signal(empty); // producer ko notify consume(item); } }

2. Dining Philosophers

5 philosophers, 5 forks. Har ko 2 forks chahiye. Deadlock possible!

semaphore fork[5] = {1,1,1,1,1}; philosopher(i) { while(true) { think(); wait(fork[i]); // left wait(fork[(i+1)%5]); // right eat(); signal(fork[i]); signal(fork[(i+1)%5]); } } // Deadlock avoid: max 4 philosophers allowed

3. Readers-Writers

semaphore mutex = 1; semaphore rw_mutex = 1; int read_count = 0; writer() { wait(rw_mutex); // write signal(rw_mutex); } reader() { wait(mutex); read_count++; if(read_count == 1) wait(rw_mutex); // first reader blocks writers signal(mutex); // read wait(mutex); read_count--; if(read_count == 0) signal(rw_mutex); // last reader unblocks writers signal(mutex); }
Problem: Writers ko starvation ho sakti hai agar readers lagatar aayein.

2.6 IPC

1. Shared Memory

  • Memory block jo dono processes access kar sakein
  • Fast (direct access), synchronization khud karna padta hai

2. Message Passing

  • Messages bhejte hain, system calls lagte hain (slow)
  • Types: Synchronous/Asynchronous. Examples: Pipes, Queues, Sockets

2.7 Threads

Thread = lightweight process. Code/data share, apna stack/registers/PC.

FeatureUser-LevelKernel-Level
ManagementLibrary handleKernel handle
CreationFastSlow (system call)
BlockingEk block = poora processBaaki safe
MultiprocessingEk processor peMultiple processors pe

2.8 Security Issues

  • Buffer Overflow: Buffer se zyada data, memory overwrite
  • Deadlock: Processes ek doosre ka wait
  • Race Condition: Concurrent access, unpredictable results
  • Privilege Escalation: Unauthorized higher access
  • Process Hijacking: Illegal control

3.5 DEADLOCK

Deadlock Kya Hai?

2+ processes ek doosre ke resources wait karte rahein aur koi chhodne ko taiyar na ho. Sab freeze!

Real-life: Do log narrow bridge pe - dono chahte hain dusra hatt jaaye!

Deadlock ke 4 Necessary Conditions

Ye 4 conditions ek saath honi chahiye! Agar ek bhi tut jaaye to deadlock nahi hoga!

  1. Mutual Exclusion: Resource non-sharable hai. Ek time pe sirf ek use kar sakti hai.
  2. Hold and Wait: Process ne kuch resources hold kiye hain aur doosron ka wait kar raha hai.
  3. No Preemption: Resources forcefully nahi le sakte - process khud chhode.
  4. Circular Wait: P1 waits P2, P2 waits P3, P3 waits P1 - circular chain.

Deadlock Prevention

  • Mutual Exclusion todna: Sharable resources use karo (hamesha possible nahi)
  • Hold & Wait todna: Sab resources ek saath do (all-or-nothing) ya naye maangne pe purane chhod de
  • No Preemption todna: Agar naye nahi le pa raha to hold kiye hain forcefully le lo
  • Circular Wait todna: Resources ko order me number do, sirf ascending order me maango

Deadlock Avoidance - Banker's Algorithm

Before allocating, check karo system safe state me rahega ya nahi.

Steps:

  1. Need Matrix nikalo: Need[i] = Max[i] - Allocation[i]
  2. Safe Sequence dhundho: Process jiska Need <= Available ho, use execute karo. Available += Allocation[i]. Repeat.
  3. Agar sab ho gaye to SAFE, nahi to UNSAFE.

Solved Example:

Given: 4 Processes, 3 Resources: A(6),B(4),C(3) Avail = A:1,B:1,C:0 Need = Max - Allocation Find process where Need <= Available Execute it, Available += Allocation[that process] Repeat until all done or stuck If all processes complete = SAFE STATE Safe sequence exists = No deadlock

Deadlock Detection & Recovery

Detection:

  • Single Instance: Resource Allocation Graph me cycle dhundho
  • Multiple Instances: Banker jaisa, check karo koi process complete ho sakti hai

Recovery:

  • Process Termination: Ek ek karke terminate karo ya sab abort + restart
  • Resource Preemption: Kisi se resource le lo (victim selection, rollback, starvation avoid)

Unit 4 - Memory Management

ALERT: Ye unit abhi tak dono exam me nahi aayi! Bada chance hai is baar!

4.1 Memory Allocation

Techniques:

  1. Contiguous: Process ko continuous block milta hai
    • Fixed Partition: Internal fragmentation
    • Variable Partition: External fragmentation
  2. Non-Contiguous: Alag alag jagah - Paging aur Segmentation

Relocation & Protection

  • Relocation: Logical->Physical address conversion. Relocation register use hota hai.
  • Protection: Limit register se doosre processes se bachana.
  • Sharing: Do processes code/data share kar sakte hain.

4.2 Paging

Non-contiguous allocation. Memory ko Pages (fixed size) me aur frames me divide karo.

  • Page Number + Offset = Logical Address
  • Page Table: Page -> Frame mapping
  • Pros: No external fragmentation. Cons: Internal frag (last page), page table overhead.

4.3 Segmentation

Logical units me divide - code, data, stack segments. Variable size.

FeaturePagingSegmentation
SizeFixed pagesVariable segments
BasisPhysicalLogical (program structure)
FragmentationInternalExternal
User AwarenessNahiHaan

4.4 Virtual Memory

Process ko lagta hai poora memory hai, lekin sirf zaruri parts RAM me. Baaki disk pe.

  • Process size physical memory se bada ho sakta hai
  • Page fault pe page load, nahi use pe swap out

4.5 Demand Paging

Pages tab load jab use hone ho. Page Fault = page RAM me nahi hai -> disk se load karo.

Steps:

  1. Process page access karta hai
  2. Page table check - valid bit
  3. Valid = direct access. Invalid = PAGE FAULT
  4. OS free frame dhundhta hai, disk se load karta hai
  5. Page table update, process restart

4.6 Page Replacement Algorithms

1. FIFO

Sabse purana replace. Simple. Belady Anomaly: Frames badhaane pe faults aur badh jaate hain!

Ref: 7,0,1,2,0,3,0,4,2,3 | Frames=3

Page Faults = 9

2. LRU

Sabse der se use hua replace. Most practical. Belady Anomaly nahi hota.

Ref: 1,2,3,4,1,2,5,1,2,3,4,5 | Frames=3

Page Faults = 8

3. Optimal

Sabse der baad use hone wala replace. Best theoretical, practically impossible.

Page Faults = 6 (same example as FIFO)

Comparison

AlgoPage FaultsProsCons
FIFO9SimpleBelady Anomaly
LRU8Practical, EfficientImplement mushkil
Optimal6Best possibleImpossible practically

4.7 Thrashing

Pages constantly disk pe load-unload. CPU utilization bahut kam.

Solutions:

  • Working Set Model: Har process ko utna memory do jitna recently use ho raha hai
  • Page Fault Frequency: Rate zyada hai to memory do, kam hai to le lo
  • Swapping: Kuch processes ko disk pe bhejo

Formula Sheet - Quick Revision

CPU Scheduling

TAT = CT - AT

WT = TAT - BT

RT = First Response Time - AT

HRRN: Response Ratio = (W + S) / S

Memory Management

Page Number = Logical Addr / Page Size

Page Offset = Logical Addr mod Page Size

Physical Addr = Frame Num * Page Size + Offset

Banker's Algorithm

Need[i] = Max[i] - Allocation[i]

Safe: Need[i] <= Available, then Available += Allocation[i]

Deadlock

4 Conditions: Mutual Exclusion + Hold & Wait + No Preemption + Circular Wait

Semaphores

wait(S): S=S-1; if S<0 then block

signal(S): S=S+1; if S<=0 then wakeup
